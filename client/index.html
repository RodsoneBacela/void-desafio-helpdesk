Ecossistema Transacional Fidli • Suporte Técnico & Operações (N1 / N2)

Este painel reproduz 12 falhas reais de produção. Utilize a interface visual ou a bancada técnica para inspecionar cada chamado.

🎯 Metodologia de Investigação em 4 Passos:

  1. Reprodução Visual: Na aba 1. Interface do Dispositivo, reproduza a ação do lojista e veja o erro exibido no ecrã do equipamento.
  2. Inspeção Técnica: Na aba 2. Bancada Técnica N1, analise a rota REST, os cabeçalhos (headers), os dados JSON e o código HTTP retornado.
  3. Correlação de Logs: No Console do Servidor à direita, verifique o timestamp, a severidade do log (ERROR/WARN) e os parâmetros internos.
  4. Preenchimento do Laudo: No arquivo SIMULACAO_TICKETS.md, elabore a resposta empática ao cliente, o diagnóstico técnico e a decisão de roteamento.

⚖️ Matriz de Severidade e Fluxo de Escalonamento:

  • P1 / Crítica: Falha generalizada, timeout de gateway financeiro (M-Pesa) com risco de dupla cobrança, ou indisponibilidade de VPN bancária. Ação: Escalonamento imediato para N2 / DevOps.
  • P2 / Alta: Falhas que afetam faturamento imediato (fila de SMS OTP indisponível, chave duplicada no caixa, colisão de MAC address). Ação: Tratamento prioritário com evidências.
  • P3 / Média: Dúvidas de integração, parâmetros inválidos em requisições de parceiros ou sessão expirada no terminal. Ação: Resolução direta no primeiro nível (N1).

💡 Consulte o documento GUIA_DO_CANDIDATO.md na raiz do projeto para a especificação completa de cada canal de comunicação.

O arquivo oficial para preenchimento e submissão é o SIMULACAO_TICKETS.md localizado na raiz deste repositório.

Campos Obrigatórios em cada um dos 12 Chamados:

  1. 1. Resposta ao Cliente: Redação cordial e humanizada, orientando o lojista com clareza, prazos estimados e sem uso de termos de stack trace ou nomes de banco de dados internos.
  2. 2. Diagnóstico Técnico N1: Causa raiz sustentada pelo código de status HTTP (4xx/5xx), payload retornado e evidências coletadas no console.
  3. 3. Ação / Roteamento: Especificação de quem trata o problema (Resolução local N1 vs Escalonamento para N2 Financeiro, DevOps ou Engenharia de Software) com evidências anexadas.

💡 Após concluir a análise dos 12 incidentes, execute npm test no terminal para conferir a integridade dos endpoints antes da entrega.
